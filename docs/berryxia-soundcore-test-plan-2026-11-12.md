## 安装步骤与执行边界

1. 取得作者确认的正式仓库／发布页后，核对应用名、Apple Silicon 支持、最低系统版本、许可证、发布版本、安装说明及签名状态。只安装与本帖对应的发布物；其他录音豆客户端另行决定。
2. 优先使用正式安装包，放入 `/Applications/`；若只有源码，先读构建脚本，在 `~/Projects/` 保存源码，缓存／构建物放 `~/Library/Caches/`。安装记录写入 `~/Library/Logs/chat-type/berryxia-soundcore/`，运行数据沿应用官方目录。记录版本、来源链接、安装路径与退出恢复方式。
3. 从安装路径经 LaunchServices 正常启动，观察首屏、模型配置、隐私说明与权限请求。新增麦克风、蓝牙等敏感权限在具体动作前取得对应授权；普通安装授权不替代权限决定。保留其他应用的权限。
4. 优先选本地转写，核对模型来源、大小、存储路径、是否还会调用在线摘要／向量化／问答服务。模型下载限官方公开来源；付费下载、协议接受或额外账户挑战单独处理。取得本地可运行模型后，关闭应用的在线功能，并在断网条件执行文件导入与转写。
5. 录音、转写、摘要、问答分别核对数据去向。在线模式需要说明供应商、凭据、收费、发送数据与失败行为，并取得对应授权后测试；本轮不填在线 Key、不调用计费端点。
6. MCP 在读取正式工具清单、确认本地传输方式、访问范围与写入能力后，再按必要授权连接。只接测试资料；不向局域网／公网开放服务，不把未核实的服务加入全局配置。

遇到来源不符、无法解释的数据外传、安装器要求关闭系统保护或获取无关权限，停止相关步骤并记录具体问题。安装失败沿原安装路径诊断；本任务不修改系统保护设置。

## 测试资料与计分

使用专门录制、无个人隐私的测试音频。每个样本保留原音频、人工逐字稿、关键事实清单、应用原始转写及最终整理稿。录音来源与合成来源分开记录；合成音频只用于导入流程与可重复实验。

| 编号 | 内容与时长 | 检查重点 |
| --- | --- | --- |
| A1 | 普通话清晰独白，30 秒 | 基础识别、导入、播放 |
| A2 | 中英混说，60 秒 | ChatType、Codex、MCP、路径与产品名 |
| A3 | 否定与范围指令，2 分钟 | “只修改标题”“不要发送”“预算不超过三千元” |
| A4 | 口头更正，2 分钟 | 周三改周四、三人改两人，最终意图 |
| A5 | 轻声说话，5 分钟 | 音量与断句；注明录音方式 |
| A6 | 可控环境噪声，5 分钟 | 漏字、幻觉、时间与金额 |
| A7 | 两人讨论，15 分钟 | 长录音完整性、会议待办、发言归属（若支持） |
| A8 | 静音，10 秒 | 无虚构正文；空结果处理清楚 |

共 8 个有效音频文件，其中 7 个语音样本、1 个静音样本；另备 1 个损坏的测试音频文件。支持格式从正式文档确认；A1 再转换为文档支持的第二种格式，并单独列出格式测试结果。重复导入同一 A1 单列为一次操作测试。

以下数值是本轮建议验收线，执行前固定；结果保留所有失败样本：

- 识别：清晰中文 A1、A3、A4 的字符错误率各 ≤5%；A5、A6 各 ≤12%。字符错误率按替换＋删除＋插入数除以人工稿字符数计算；统一去标点、空白，保留数字与否定词。A2 另列专名逐项正确率。
- 意义：A3 的否定／范围／预算及 A4 的更正结果逐项全对；A7 的人工标注待办、负责人、时间逐项核验，杜撰事实为失败。最终整理稿单独评分，保留转写原稿。
- 完整性：8 个有效文件逐个有明确成功或错误状态；成功文件可播放、可定位和持久保存；A7 的开头、中段、结尾均有人工核对结果。
- 性能：记录模型冷启动耗时；热运行 A1、A3、A7 各 3 次，记录转写耗时、音频时长、峰值内存及界面是否响应。以耗时／音频时长衡量处理速度，建议中位数 ≤1。安装或模型下载耗时另列。

## 执行顺序与通过标准

| 阶段 | 操作 | 可观察通过标准 | 失败动作 |

| T1 安装与启动 | 按官方步骤安装、正常启动、退出、重启 | 版本／路径一致，首屏可操作，数据重启后保留 | 保存脱敏错误，修复安装问题；不进入业务验收 |
| T2 文件闭环 | 逐一导入 A1—A8、第二格式 A1；回放、转写、查看记录 | 每项状态清楚；文本、时长、录音对应；原音频保留 | 定位格式／模型／存储阶段；保留失败输入 |
| T3 质量与性能 | 按上述固定逐字稿、事实清单与次数计分 | 各项达到建议线；逐样本结果可复核 | 报具体漏词／错意；不靠总平均掩盖单项失败 |

| T5 知识库 | 对 4 个有答案问题与 4 个资料外问题逐一提问 | 有答案项返回正确录音及可核对原文；资料外项清楚说明缺依据 | 区分检索错、引用错、生成错；有事实杜撰即失败 |
| T6 场景与看板 | 对会议、沟通、灵感样本人工标类别；核对条数、时长、星标、分类 | 每项与测试记录一致；允许人工纠正且重启保留（若提供入口） | 功能缺失列“不支持”；统计错列失败 |
| T7 本地隐私 | 模型准备完成后，断网重复导入与转写；检查官方说明、日志及可用连接观测 | 本地转写可离线完成；在线依赖逐项说明，异常连接可追查 | 对未经批准的外传暂停对应功能 |
| T8 助手检索 | 通过 Codex 调用已核实的 MCP 测试工具，复用 T5 的 8 个问题 | 可按已公布工具取得同一录音与证据；错误／无结果可理解 | 保留工具名、脱敏参数和返回；禁用故障测试连接 |
| T9 硬件闭环 | 按下节录音豆步骤执行 | 实物录音、传输、识别、检索全链路通过 | 标明设备／固件／连接阶段；保留原录音 |

T5、T8 的 4 个有答案问题分别查 A3 的预算限制、A4 更正后的日期、A4 更正后的人数、A7 的具体待办；另外 4 个问题询问未录入主题／不存在的人名或金额。问答实际需要在线模型时，等待该模式的授权，先完成离线转写项。

“上周某主题”的检索单独检查应用对周界和时区的定义，并使用真实日期已知的测试记录。若公开导入界面支持保留／设置录音日期，建立跨周样本；否则将此项标为“缺少跨周资料”，不直接修改数据库或把文件名日期冒充录音日期。

断网通过只覆盖离线功能可用性；网络观测只报告工具实际覆盖范围。隐私结论同时列官方声明、配置、已观察连接与尚未知的数据路径。

## 录音豆实测分支

需要真实 soundcore Work／作者明确支持的型号；执行前记录型号、固件、电量、原客户端连接状态，并协调单一蓝牙连接占用。新增权限按动作授权。

1. 扫描、选择与连接目标设备，核对名称、电量和真实连接状态；重连 3 次。
2. 在设备上分别录制 30 秒与 5 分钟测试内容，经客户端读取、传输并播放，对比时长、首尾完整性，再执行转写和知识库检索。
3. 在测试录音传输中断开再恢复，核对缺失／重复／损坏情况。原始录音保留；禁清空、格式化、刷固件或恢复出厂。
4. 若应用声称支持实时输入或设备按钮触发，按官方入口逐项测试，记录实际支持范围；录音文件同步与实时麦克风分别验收。
5. 结束后留客户端正常运行；如测试临时占用蓝牙连接，恢复用户原来使用的连接方式。

无硬件时可执行 T1—T8 中已满足授权与依赖的项目，T9 始终单列为“未执行：缺设备”，整体验收保持部分完成。
