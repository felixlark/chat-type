# ChatType 全面精简、清理、优化与提升方案

## 目标与当前事实

把当前产品整理成一条可理解、可验证、可安装的主链：F5 录音 → 实时初稿 → 所选 ASR → 术语对齐 → 所选润色 → 修正规则 → 有回执的写入或剪贴板。清掉已被取代的要求、死代码、重复测试、废弃实验和重复交付入口；保留仍有用户的能力与数据。清理不以删除行数或降低测试数量为目标。

当前 Git 跟踪 277 个文件、3,473,772 字节；其中 Sources 81 个、Tests 60 个、docs 82 个、scripts 32 个。Swift 产品代码约 16,587 行。`PreferencesWindowController` 1,473 行、`AppCoordinator` 1,342 行、`TerminologyNormalizer` 1,058 行。行数用于定位混合职责，不作为拆分配额。Git 对象约 9.74 MiB，未发现 Git 垃圾对象；不是需要强推重写历史的大仓。原始计量见同目录 `baseline.json`。

安装版 doctor：签名有效，LSUIElement=true，正常进程运行；ASR、润色当前均为 doubaoIME。未对清理候选运行基线测试或安装版验收，不能据此判定产品健康。

最初盘点时，另一个任务持有输入预览／粘贴修复现场。现已核对：其 WIP 保存为分支 `codex/preview-anchor-and-receipt` 的 `9dc8b1e`，canonical checkout 已切回 `main`、`5350f037` 且 clean，writer 已释放；安装版仍是 build 138，WIP 139 没有安装。该用户最新批准由原任务实现顶部 HUD＋下方黑底白字字幕，放弃输入框旁字幕；清理不并发实施该独立 UI 任务，也不恢复或删除 WIP。

保持一个原生 macOS 应用，不新建服务、插件总线或通用状态机框架。

## 实施顺序与验收

同一负责人连续交付，各批是可独立回滚的变更，不另建 Task／Goal。

1. **接入当前修复与基线**：从原 PR／Git 状态确认 writer 释放，核其提交、真实安装版和已完成验收；取最新主线作为整合基线。运行 doctor、现行非 GUI 检查，失败分清旧基线故障与清理引入故障。保留旧变更，不替别人提交。基线及新指标补入交付账。
2. **合同和明显死代码**：先收敛上述四类当前文档，生成保留／合并／删除清单。处理 AuthConfig、死视图、旧别名和只为死路径存在的测试。保留配置迁移、权限首启、取消、Retry、输出回执、键位和品牌回归。每项删除都含依赖闭包复核及相关行为证据。
3. **退出废弃实验**：以脚本→CLI→资源→测试→文档链分组；保留仍有用的质量工具，删除已被取代的实验。本轮不拆独立 target；保留有用途入口并记录理由。
4. **整理架构**：整理设置视图和服务工厂，只处理有证据的词库重复；每步迁移调用者后删除旧代码。保留 Session 两类身份及原状态，不进行尚无缺陷证据的状态模型重写。复用现有协议和测试缝，不添加仅供未来使用的扩展点。此批不改变视觉和服务目的地。
5. **测试和部署收敛**：移除只匹配实现文字或只服务废弃能力的测试；保存仍承担唯一业务保护的断言。CI 运行与本地相同的无 GUI 源码检查；对打包脚本的改动核同一份产物的版本、签名、资源与依赖。一个 release build，安装 `/Applications/ChatType.app`，真实验收后留正常进程运行。
6. **仓库瘦身与最终交付**：记录前后文件／字节／Swift 行数／Git 对象／包体与耗时（只测本次需要的项）；检查链接和入口不悬空。待 writer／Git 操作都结束，用 `git repack -d`（不加 -a/-A，不运行 gc／reflog expire／git prune） 压缩可达对象并保留恢复对象和 reflog；前后校验全部对象 ID 集合、refs、reflog 和 worktree 元数据不变，另跑 fsck。提交、PR、项目要求的 Codex 自动评审及阻塞意见处理完成后合并。内容 PR 顶部给稳定 Markdown 成品预览链接并从读者入口核对版本。

每批失败直接修复当前原因；撤回时 revert 该批提交并重新打包安装旧候选，保留用户配置和恢复记录。涉及持久化格式的迁移不得混入无迁移策略的回滚批次。

最终安装版最小旅程：真实编辑目标中 F5 开始、F5 停止，确认初稿与最终文本；ESC 和关闭取消后可再录；有错误时 Retry 保留原路线；输出回执与剪贴板分支真实可见；四页设置保存正常，菜单栏常驻。只测受影响分支，复用同一版本仍有效的证据。后台 OCU 不能完成的动作准确记未验，在用户空闲时完成，不抢人工焦点。

## Git 历史边界

删除 HEAD 文件只减少工作副本及未来树，不会删除历史 blob。增量 `git repack -d` 只证明本地对象压缩，不证明 GitHub 远端历史变小。本仓当前约 10 MB，优先清理逻辑和现役文件，不强推。只有审计发现确切的大对象或敏感内容，才准备包含 refs／tags／旧提交链接影响、恢复 bundle 和逐项对象清单的历史重写方案，取得对应明确授权后执行；不以本次“瘦身”笼统指令删除用户分支、tag、reflog 或不可达恢复对象。

## GSE 可复用能力

把这次完整要求落在 GSE 的 `references/legacy-project-cleanup.md`：覆盖需求、架构、代码、测试、部署、文档、依赖、资源与 Git；先审计和决策清单，再在实际授权内清理交付。GSE 入口和技能描述支持“用 GSE 清理这个陈旧项目／屎山项目”触发。专门简化、影响分析、独立评审和验收仍调用当前独立技能，不复制方法。方案模式与实施模式遵用户实际措辞，不能将只出方案自动扩成删代码，也不能在已授权清理时停在建议。
