# ChatType 保留交互、接入豆包输入法后端：调研与实施方案

日期：2026-11-14。当前状态：协议调研已完成，用户随后明确批准实施、保留 ChatGPT 及豆包默认；126 已实现并安装，最新验收见[实施记录](doubao-implementation-2026-11-14.md)。结果负责人：本 chat 主 Agent；产品决定人：Longbiao。下文研究阶段的限制与结论保留其当时范围；实施合同见第 10 节。

## 1. 用户结果与建议

保留 ChatType 的 F5 开始／停止、浮层、取消、术语管理、录音留存、历史回看、重试和保守粘贴，把语音识别和文字润色交给**豆包输入法实际使用的后端**。ASR（Automatic Speech Recognition）就是语音识别，与 STT（Speech to Text，语音转文字）在本需求中指同一阶段；不是两项服务。

本轮已经取得「配置凭据 → ASR → 独立文字整理」的最小真实重放，详见[协议调研实测报告](doubao-protocol-research-results-2026-11-14.md)。建议下一阶段在这些已观察的协议上细化显式实验路线；本条样本的识别与改口质量未通过，不能直接切换默认。火山引擎商业 API、豆包聊天网页、自动切换原输入法均不能代替目标后端的验证。

这条方向的价值是让录音与个人习惯由 ChatType 掌握，服务端负责识别和整理；它不会天然解决豆包服务本身的断线、超时或质量问题，必须通过本地持续落盘和可恢复会话来消除内容丢失。

## 4. 阶段 R：取得可复核的完整协议

这是后续接入的先决研究阶段，不改 ChatType 默认路线。本轮已运行 `scripts/doctor.sh`，安装版 125 正常运行，默认仍为原 ChatGPT 路线。下面保留研究合同；已完成项与剩余缺口以[实测报告](doubao-protocol-research-results-2026-11-14.md)逐项读回，不能将最小重放成功扩大为整套生产验收。

1. **固定研究对象。** 对本机安装包读取版本、签名、架构和 SHA-256；静态检查资源、网络相关符号、消息定义与调用关系。候选端点须记录所属二进制和引用位置，不能只凭字符串宣称实际调用。原生深析依赖所选引擎就绪，未就绪时明确保留缺口。
2. **受控观察。** 用新写的非敏感短句，分别开／关豆包智能整理、带术语和改口、长录音、手动停止，关联同一会话的网络事件与最终可见输出。GUI 沿官方 Computer Use，真实硬件输入沿 KVM，保持单操作者并恢复临时快捷键和输入源。先取必要元数据；当前没有证据表明 TLS 明文已可见。需要抓取明文而现有方法不足时，报告确切依赖与权限，不自动安装根证书、持久化代理或修改目标签名来打通流程。
3. **建立协议合同。** 记录 HTTP 方法／路径或 WebSocket 消息、字段类型与含义、编码、帧长、采样率、发送节奏、会话 ID、序号、状态与结束条件。用“证据／推断／未知”标识字段，不把 Android 帧枚举直接认作 macOS 事实。认证值不进入日志；只保留凭据来源、生命周期和脱敏状态码。凭据由受支持流程取得并存 Keychain；不导出浏览器 Cookie 或复制其他产品的 OAuth token。
4. **分别证明识别与润色。** 同一测试句观察整理关闭／开启的请求差异、中间输出与最终改字。若后端内建整理，则记录为联合流程，确认怎样取得最终稳定文本；若只有联合文本，审计中的“原始 ASR”必须标为不可观测。若有独立润色，再验证文本输入、上下文／术语支持和保真边界，不能猜一个聊天端点补齐。
5. **最小重放。** 在既定官方服务与合法可复用认证方式确定后，用自有非敏感音频在隔离研究工具中复现一遍完整流程；再验证新会话、重启／凭据过期、取消和断网。重放记录本地样本 SHA、协议版本和最终完成信号。不得自动注册大量虚拟设备、刷新凭据绕过挑战或重复未知副作用。

产物：可脱敏的协议说明、离线请求／响应夹具、端点与消息来源表、认证／费用／数据流说明、最小重放结果、未知项。日志放 `~/Library/Logs/ChatType/doubao-research/`；研究工具／依赖放 `~/Library/Application Support/ChatType/DoubaoResearch/`，缓存放 `~/Library/Caches/ChatType/`。只保存必要受控内容，凭据与认证请求体在持久化之前排除，避免先落盘再脱敏。

**阶段结论必须明确：** 完整流程可重放才进入集成；只有 ASR 则局部可行；需无法复用的客户端身份、挑战或未获许可的收费路径则把该项列为阻塞，继续可独立的本地设计与夹具工作。商业火山 API 是独立备选，需要单独核定账户、计费和用户决定，不能静默替换。

阶段 R 出口先依据实证更新本方案，冻结会话接口、状态迁移、持久化字段、实际改动清单、服务规定／相称的重试策略及夹具断言，再进入产品编码；阶段 I 下面的类型名只是架构草案。数据流与费用条件随该候选明确呈现，不能拿本次“提出方案”当作产品实施授权。

## 5. 阶段 I：ChatType 适配设计

### 5.1 保留交互，扩展会话与流水线

建议新增显式 `doubaoIME` 实验路线，保留既有两条路线的配置兼容和行为；不暗中降级到 ChatGPT，也不向它发送豆包失败录音。最小方案采用本轮实测的 ASR 配置 key 与独立整理端点，不要求用户登录或引入 SAMI／Wave／NER。它是当前可用的私有服务行为，凭据刷新及服务拒绝必须真实显示，不承诺长期匿名可用或免费。切默认、实际产品实现和发布沿后续明确执行范围办理。

```text
F5 开始 → 本地 WAV / journal 持续保存
        → 同一音频源分流给豆包会话 → 中间文本更新原浮层
F5 停止 → 封口本地录音 → FinishSession → 等到 SessionFinished
        → 对完整 ASR 做本地术语对齐 → 豆包 text_organization
        → scene.completed + done → 本地术语／纠错规则
        → 保存各阶段记录 → 一次性粘贴或剪贴板
```

本地词表、录音和注入保持由 ChatType 控制，先复用已有术语对齐和纠错；独立整理的 query 可接收对齐后的文本，审计同时保留原始 ASR、实际整理输入、原始整理输出及终稿。本轮最小整理 schema 没有证明可发送自定义系统提示或词表字段。云端识别热词仅列为待验证能力：上游有“字段接受但效果不可观察”的反例，不能据此宣称学会了用户新词。本地替换不能找回所有漏词；也不能用强制删除“上午十点”等特例掩盖语义错误。此路线不再进入 ChatGPT 润色。

当前 `Transcriber.transcribe(RecordedAudio)` 只有停录后文件输入；流式接入需新增会话接口与共享音频分流。先用阶段 R 的文件重放适配器证明完整功能，再复用验证过的协议加实时会话，避免同时追查编码、生命周期和产品行为。文件模式只算中间验收，不能用它承诺豆包实时速度。

### 5.3 打断、恢复和审计合同

- 云端断开不停止本地采集；网络队列用磁盘音频与发送游标承接，不在内存无限堆帧。恢复是服务端断点续传还是新会话重放，由阶段 R 证据决定；未证实续传时不拼接两份可能重叠的结果。
- **采集中断独立处理。** 以单调时钟与已接收帧的推进检测回调停滞，分别处理设备断开、休眠与采样格式变化，不能只检查电平或云端状态。确认中断后进入 interrupted，安全封口并保留已接收前缀，停止自动提交和粘贴；记录最后接收帧时间、有效区间及未知／缺失区间，不能声称整段原声完整。设备恢复后由 F5 明确开始新段，以 parentRecordID／segmentID 关联原记录，不向旧 WAV 补假静音或无缝续写。默认不自动唤醒麦克风；重放已收前缀需用户显式选择，并标明局部音频。软件无法恢复设备未交付的样本。
- **存储失败独立处理。** 保留现有“WAV／journal 不可写就不开始，运行中保存失败立即停止采集”的规则；音频写入、同步或审计元数据保存失败都进入可见的 persistenceFailed，取消云端处理与自动注入，尽力封口已落盘前缀。不能继续采集后宣称完整审计，也不能忽略 `recordRecoverySuccess/Failure` 的写入错误后报告完整成功；若文字已由服务器返回，只可暂存内存并明确提示尚未可靠保存。磁盘仍不可写时无法保证错误标记自身持久化，须保留已有文件、即时显示失败，恢复可写后再完成记录，不声称已保存。修复后重新校验 WAV／journal，恢复操作由用户明确触发，不删除原件。
- F5 停录只关闭本次采集，仍等待最终完成信号。中间文本不粘贴。取消后释放麦克风与连接并保留已录音；取消令牌和 sessionID 阻断迟到的结果、润色、重试及注入。
- 自动恢复仅在可判定的瞬态错误与已验证的重放语义下启用，次数／退避由实测和既有政策定稿；不在此方案杜撰新固定上限。鉴权失效、服务挑战、限流与格式错误分别显示，避免无限刷新或伪装成功。
