# 本机候选报告与分层姓名检索：实施合同

用户已批准通讯录优化方案。先实施本机报告和分层姓名检索的离线对照；原始联系人合并/删除仍逐组批准。当前模型、词库、重点词及整段润色保持。新姓名清单先独立验收，真实转写继续原路径，符合已评审方案的采用门槛。

## 入口与数据边界

新增正式只读命令contacts-report，由现有ChatTypeCLI在main构造AppDelegate之前分流。通过LaunchServices启动/Applications/ChatType.app的新进程执行；后台线程用Apple Contacts公开框架读本机姓名/昵称/结构化姓名/组织名/标识/来源。只接受已有authorized授权，不请求权限、不创建认证管理器、不调用模型/网络、ConfigStore.load/save或CNSaveRequest。配置用独立最小结构只读解码entries，保留原始字节。

命令输出只有匿名计数、耗时和本机报告路径。姓名、标识和来源名称仅写Application Support/ChatType/ContactsReports下的本机文件，目录0700、文件0600；模型、日志和仓库不接收真实通讯录字段。报告和姓名清单按独立生成目录提交：同目录暂存全部文件后重命名发布；失败保留上个完整报告。

## 原生快照

分别取原始与统一卡片，联系人字段固定为identifier、contactType、formatted fullName、given/middle/familyName、nickname和organizationName；手机号、邮箱、备注、照片和地址不读取。来源名称只留本机报告。先取标识，随后读取姓名，标识集合发生变化则中止本次发布。联系人变更通知在采集期间出现同样中止；下次命令重新读取。

按非空个人显示姓名分组，昵称另分组；空姓名和组织卡片单列。同名候选的原始关联使用CNContact.isUnifiedWithContact公开方法，仅对候选卡片关联源记录，避免全部卡片的全量两两比较。来源无法关联时标明未知，不猜来源或身份。

## 清单与检索

每个字形记录原始写法、角色集合（姓名/昵称/机构/通用词/待核）、全部来源和本机原始联系人标识。同字形允许关联多个联系人；不同汉字及同音字保持独立。姓名/昵称与机构字段分别建角色；旧来源无法确定的词保持待核，原始词库全部保留。user、Text Replacement纠正映射及优先规则保持。

本机姓名检索沿用现有PersonalNameHints规则，以角色筛选后的姓名/昵称和待核旧姓名候选作为输入；机构独占词不进入姓名候选，但继续留在通用词表。新清单只供本机对照，不接入DictationPipeline、ASR提示或整段润色。当前近音门槛导致的失败单列，不把分层清单的生成视为姓名识别修复。

可选--check-cases读取本机JSON样本（id/text/expected），对原词库和分层清单各跑一次冷查询及预热后5轮，记录匿名召回位置数/候选数/耗时；报告中敏感值仍仅本机，stdout只计数。测试覆盖原成功、实际失败和普通词负例。原600/240提示预算不变；本次不新增重点词或放宽匹配门槛。

## 本机报告

静态HTML，无脚本/外部资源，全部联系人与词库字符串HTML转义，CSP阻止外部资源加载。显示来源账户与计数、同名/同昵称候选、原始来源关联、字形角色统计、619项旧来源缺席候选的当前重新核对。缺席仅作来源核验；同时对全部来源标准字形与别名检查实际覆盖。报告包含只读范围和未判身份声明。

本机保存name-catalog.json便于后续复测；schema不支持时重新生成，不迁移或覆盖原词库。实体合并/删除和同步账户写入均没有命令入口。
